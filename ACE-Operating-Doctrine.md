# ACE Operating Doctrine

> **Historical governance doctrine, version 0.2, published 2026-06-09.**
>
> This file is preserved because several useful ideas still appear in later work: closed by default, evidence first, human bounds, fail-closed behavior and receipts over claims. The ACE name here is historical provenance. It is not the current parent identity of Asso or SYSTASYS, and this document is not a source of current runtime state or authority.

ACE was published here as an applied operating doctrine for agentic governance: closed by default, evidence first, human bounds and receipts over claims.

It was designed for AI-agent work that needs to stay bounded, reviewable and revocable.

Autonomy without governance is not intelligence. It is liability.

## Core principles

### 1. Closed by Default

Nothing is allowed unless it is explicitly admitted by the active boundary.

Unexpected input, missing evidence, schema mismatch, stale state, unclear authority or unsafe scope should halt the path instead of being guessed through.

### 2. Evidence First

Receipts over claims.

An agent saying "done" is not enough. Preserve inspectable evidence of what was proposed, what was checked, what was refused, what changed and what still requires human review.

### 3. Human Bounds

Human authority remains explicit.

Agents may propose, prepare, summarize, transform or execute inside a valid envelope. They do not create their own authority or expand their own scope.

### 4. Admissibility before action

An action should be admitted only inside an explicit envelope: mandate, boundary, evidence, stop conditions, handoff and rollback where relevant.

### 5. Receipts make boundaries visible

A receipt is not marketing proof and not formal verification.

It is an evidence trail intended to make later review possible and reduce false readiness claims.

### 6. Fail-Closed by Default

When a system cannot prove that an action is allowed, it should stop, surface the reason and require review.

Fail-open behavior is treated as a defect.

## Public and private boundary

Public artifacts can demonstrate doctrine through bounded documentation, SOPs, receipts, examples and audit trails.

They do not grant runtime authority, merge authority, trading authority, publishing authority or permission-to-act.

## Historical public artifacts

This doctrine appeared alongside early public artifacts such as Asso Lab, AI Ops SOP Pack and the ACE Agent Governance Receipt Standard. Those objects remain useful as dated public evidence, but they do not define the current SYSTASYS architecture.

## Language discipline

Use concrete failure modes before doctrine. Use public artifacts before claims. Do not claim production readiness, formal verification, autonomous permission-to-act, client adoption, revenue, live execution or runtime availability without explicit evidence.
